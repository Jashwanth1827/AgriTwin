# AgriTwin Architecture

This document describes the implemented architecture, not an aspirational design. Every layer listed here exists in the repository and is exercised by tests or the end-to-end smoke test.

---

## 1. Design principles

1. **The decision engine is a pure, testable module.** It has no FastAPI, SQLAlchemy or network dependencies. The service layer converts database rows into typed inputs and persists the result.
2. **Uncertainty is first-class.** Yield and price forecasts carry intervals; those intervals feed the risk score, the revenue bounds and the INSPECT rules.
3. **No silent fake data.** Every demo or fallback path is labelled in the API (`model_mode`, `is_demo`) and in the UI.
4. **Chronology is respected.** Yield and market models are validated on future periods, never random splits.
5. **Explainability is an output, not a log line.** Decisions return factors, assumptions, missing inputs, freshness warnings and scenario values.
6. **Ownership isolation is enforced at the data-access boundary.** Services take the authenticated user and filter by `user_id`.

Alembic owns schema evolution:

```powershell
cd backend
alembic upgrade head
alembic downgrade base
alembic upgrade head
```

The initial migration is `backend/alembic/versions/20261104_0014_709bc5e375e1_initial_schema.py`. In development the app also calls `Base.metadata.create_all` for convenience; in production (`ENVIRONMENT=production`) it does **not**, and the container runs `alembic upgrade head` before Uvicorn.

### Layer 3 — ML / inference

| Model | Implementation | Artifact | Mode |
| --- | --- | --- | --- |
| Crop health | ConvNeXt-Tiny, 38 classes, 192 px, ImageNet transfer learning, metadata-driven 4-view TTA, soft crop prior (`alpha=0.95`), Grad-CAM on the last ConvNeXt block | `crop_health/model.pt` (111,452,123 bytes) + `metadata.json` | `real` when weights load; labelled `demo` heuristic otherwise |
| Yield | ExtraTrees regressor over crop/season/state/area + expanding history features; split-conformal 80% intervals | `yield_prediction/model.joblib` + `metadata.json` | `real` when the bundle loads; transparent `historical_average` fallback |
| Market | Seasonal naive, moving average, linear trend with weekly dummies, random forest, gradient boosting; chronological tail validation; empirical residual intervals | No persisted model; computed on demand | `on_demand` |

Inference services are process-wide singletons with lazy loading and thread locks. They never crash the API when an artifact is missing; they report `available=false` or fall back with an explicit mode.

Details: [ML_PIPELINE.md](ML_PIPELINE.md).

### Layer 4 — Decision

Pure modules under `backend/app/services/decision/`:

| Module | Responsibility |
| --- | --- |
| `policy.py` | Loads and validates `config/decision_policy.json`; enforces risk weights summing to 1.0 |
| `models.py` | Typed dataclasses for inputs, buyer evaluations and outcomes |
| `risk.py` | Eight weighted risk components + risk-adjusted net |
| `fusion.py` | Completeness, confidence, freshness, revenue bounds |
| `engine.py` | Buyer eligibility/ranking, immediate vs wait scenarios, ordered rules, explanation |

The engine never touches the database. `decision_service.py` builds the inputs from persisted predictions, offers, weather and routing, calls `decide()`, then persists the decision and factors.

Details: [DECISION_ENGINE.md](DECISION_ENGINE.md).

### Layer 6 — API

FastAPI with versioned routers under `/api/v1`. Cross-cutting concerns:

- **Authentication** — `HTTPBearer` + JWT decode; `CurrentUser` dependency loads the active user.
- **Ownership** — farm-scoped dependencies return `403` for non-owners; service-level lookups return `404` to avoid leaking existence.
- **Validation** — Pydantic v2 schemas, constrained fields, enum-like validators.
- **Uploads** — MIME allow-list, 8 MB limit, 4096 px dimension limit, SHA-256 dedupe.
- **Rate limiting** — in-memory sliding window, 120 requests/minute, 20 for auth routes; configurable and disabled in tests.
- **CORS** — explicit configurable origins.
- **Logging** — structured JSON with request IDs and latency.
- **Errors** — consistent envelope: `code`, `message`, `details`, `request_id`.
- **Health** — `/system/health` (liveness + DB) and `/system/status` (model modes, metrics, data freshness).

React 18 + TypeScript + Vite. Tailwind CSS with shadcn-style primitives (button, card, input, dialog, badge, table, alert, spinner, empty state). TanStack Query for server state, React Hook Form + Zod for forms, Recharts for charts, Lucide icons, React Router.

## 3. Key request flows

### 3.1 Crop-health scan

```
POST /api/v1/crop-health/predict (multipart)
  → auth + farm/crop ownership
  → validate MIME, size, dimensions
  → SHA-256 dedupe (reuse existing upload if identical)
  → CropHealthService.predict(image, crop_hint=farm.crop_name)
      → preprocess per view (resize 240/216, center crop 192, ImageNet normalise)
      → 4-view TTA: ConvNeXt-Tiny forward on original + flip at two scales
      → average softmax probabilities
      → soft crop prior alpha=0.95 when crop maps to a trained group (else no-op)
      → label, confidence
      → severity + advisory from labels.py
      → Grad-CAM on last ConvNeXt block (base view) → overlay PNG
  → persist UploadedFile + CropHealthPrediction
  → return prediction with model_mode and gradcam_url
```

If `model.pt` is absent, the service returns a clearly labelled `demo` heuristic with `is_demo=true`; the UI shows a warning banner.

### 3.2 Yield prediction

```
POST /api/v1/yield/predict {farm_id, crop_id}
  → ownership
  → build features: crop, season, state, area, log_area,
    crop_state_hist_avg, crop_hist_avg, state_hist_avg
  → ExtraTrees.predict → q/ha
  → scale by crop.area_hectares → total quintals
  → apply split-conformal half-width → 80% interval
  → confidence from input completeness and interval width
  → persist YieldPrediction
  → return point estimate, interval, features, completeness
```

`GET /yield/readiness/{crop_id}` uses the crop calendar and harvest date to return `ready`, `approaching`, `not_ready` or `unknown` with days remaining.

### 3.3 Decision

```
POST /api/v1/decisions {farm_id, crop_id, risk_preference, ...}
  → ownership
  → resolve or auto-compute:
      yield prediction (latest or new)
      market forecast (latest or new, state-preferred market)
      crop-health scan (latest, optional)
      weather risk (Open-Meteo, optional)
      buyer offers + transport quotes
  → build DecisionInput
  → engine.decide():
      completeness → buyer evaluations → immediate channel
      → risk score → wait scenario → ordered rules
      → explanation, factors, assumptions, bounds
  → persist Decision + DecisionFactors
  → return full outcome
```

### 3.4 Market forecast

```
POST /api/v1/market/forecast {crop, market?, horizon_days}
  → pick market (preferred state when enough observations)
  → load daily price series
  → require ≥ 21 valid observations
  → chronological tail validation (7–21 days)
  → compare 5 candidates by MAE
  → refit best model on full history
  → recursive/structural forecast for horizon
  → empirical 80% residual interval, widened by √step
  → persist MarketForecast with metrics and comparison
```

Sugarcane has only 7 observations and correctly returns `422 insufficient_data`.

## 4. Security architecture

| Control | Implementation |
| --- | --- |
| Password storage | bcrypt, per-password salt |
| Access tokens | HS256 JWT, 60-minute default expiry, `sub` + `type` + `jti` |
| Refresh tokens | 7-day default, rotated on refresh; revoked `jti` persisted |
| Logout | Revokes the presented refresh token |
| Ownership | `user_id` filter in every service query; 403/404 split documented above |
| Uploads | MIME allow-list, size limit, dimension limit, image verification, SHA-256 dedupe |
| Rate limiting | Sliding window keyed by client + path class; auth routes stricter |
| CORS | Explicit origin list from configuration |
| Secrets | Environment variables; `.env` ignored; development defaults clearly marked |
| SQL injection | SQLAlchemy expression language, no string-built SQL |
| Error leakage | Generic messages; internal exceptions logged with request ID |
| Production schema | Alembic only; `create_all` disabled |
| Demo data | `is_demo` flags on users, farms, buyers, offers, predictions |

## 5. Data freshness and degradation

AgriTwin is designed to work offline and to be honest about what is missing.

| Dependency | Failure behaviour |
| --- | --- |
| Crop-health weights | Labelled demo heuristic; `model_mode="demo"` |
| Yield artifact | Historical state/crop average; `model_version="historical_average"`; wider interval |
| Market history < 21 days | `422 insufficient_data`; no fabricated forecast |
| Open-Meteo | Weather marked unavailable; risk floor applied |
| OSRM | Geodesic distance × 1.25 detour factor; `distance_method="approximate"` |
| Buyer coordinates missing | Transport cost excluded and flagged as an assumption |
| Stale prices | Freshness risk component + INSPECT rule beyond 90 days |
| No buyer offers | Mandi channel only; buyer risk component marked unavailable |

## 6. Deployment topology

```
docker compose
├── db        postgres:16-alpine  (healthcheck: pg_isready)
├── backend   python:3.12-slim    (alembic upgrade head → uvicorn :8000)
└── frontend  nginx:1.27-alpine   (serves dist, proxies /api and /uploads)
```

- Named volumes: `postgres_data`, `uploads`.
- Backend healthcheck: `GET /api/v1/system/health`.
- Frontend healthcheck: `GET /`.
- Frontend waits for the backend to be healthy; the backend waits for PostgreSQL.
- CPU-only PyTorch wheels keep the backend image smaller.

For local development, Vite proxies `/api` and `/uploads` to `http://localhost:8000`, and SQLite removes the need for PostgreSQL.

## 7. Testing strategy

| Level | Tooling | Coverage |
| --- | --- | --- |
| Decision engine unit | pytest | Ordered rules, buyer eligibility, risk weights, completeness, freshness, Decimal money, wait economics |
| API integration | pytest + FastAPI `TestClient` | Auth, refresh, ownership, CRUD, uploads, forecasts, decisions, reports, health |
| Frontend unit | Vitest + Testing Library | API client, utilities, auth context, storage polyfill |
| Build | `tsc -b && vite build` | Type safety and production bundle |
| End-to-end | `scripts/smoke_api.py` | Full real-model workflow including Grad-CAM |
| Migration | Alembic CLI | Upgrade → downgrade → upgrade |

Tests use a session-scoped client, a unique temporary SQLite database and a temporary upload directory, with `DEMO_MODE=true` and rate limiting disabled. They do not touch the developer database.

## 8. Extension points

- **New crop-health architectures** — add a builder branch in `backend/app/ml/crop_health/service.py` and `ml/crop_health/training/train.py`; metadata drives loading.
- **New market models** — add a predictor to `backend/app/ml/market_forecasting/forecast.py`; the chronological comparison selects it automatically if it wins.
- **New decision rules** — add thresholds to `config/decision_policy.json` and an ordered branch in `engine.py`; unit-test the branch.
- **New regions/languages** — extend `core/constants.py` and advisory text in `ml/crop_health/labels.py`.
- **Real buyer integrations** — replace the buyer/offer tables behind the existing service interface; the decision engine is agnostic to the source.
- **PostgreSQL-specific features** — the models use portable types; add dialect-specific indexes or constraints in a new Alembic migration.
